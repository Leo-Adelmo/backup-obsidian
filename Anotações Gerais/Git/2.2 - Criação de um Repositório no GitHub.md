### Introdução

O objetivo desta documentação é guiar a criação de um repositório no GitHub para armazenar todos os códigos de exercícios e estudos da Mentoria DE. O repositório será configurado para garantir que as boas práticas de versionamento sejam seguidas e que a colaboração entre os membros da equipe seja eficiente. Todos os usuários da equipe **DEVERÃO** utilizar o **Windows Subsystem for Linux (WSL)** com o **Ubuntu 22.04**, operando unicamente através do terminal.

### Resumo dos Critérios de Aceite

1. **Adicionar todos como membros com permissão de “escrita”**: Todos os colaboradores devem ter permissão de escrita.
2. **Proibir merge/push direto na master**: A branch **main** deve ser protegida.
3. **Adicionar o Eduardo como OWNER e remover o criador como OWNER**: O Eduardo será configurado como OWNER, e o criador deve alterar sua permissão.
4. **Criar um README**: O repositório deve ter um README com informações e instruções.
5. **Criar um `.gitignore` com prioridade em Python**: O repositório deve incluir um arquivo `.gitignore` adequado para projetos Python.

### Passos para a Criação e Configuração do Repositório

#### Passo 1: Criar uma Chave SSH para Conectar ao GitHub

Antes de interagir com o GitHub via terminal, todos os usuários precisam configurar uma chave SSH. Essa chave permitirá a comunicação segura entre o terminal local (WSL/Ubuntu) e o GitHub.

Você pode gerar uma nova chave SSH no computador local. Depois de gerar a chave, você pode adicionar a chave pública à sua conta em GitHub.com para habilitar a autenticação para operações do Git no SSH.

1. **Gerar a Chave SSH**:
    
    - Abra o terminal no WSL (Ubuntu 22.04).
    - Digite o seguinte comando para gerar uma nova chave SSH:
    

    ```shell
	ssh-keygen -t ed25519 -C "your_email@example.com"
	```
	 
	 Isto cria uma nova chave SSH, usando o nome de e-mail fornecido como uma etiqueta.
    
    ```shell
    > Generating public/private ALGORITHM key pair.
    ```
    
    Quando for solicitado a inserir um arquivo para salvar a chave, pressione **Enter** para aceitar o local padrão do arquivo. Observe que, se você criou chaves SSH anteriormente, ssh-keygen pode pedir que você reescreva outra chave. Nesse caso, recomendamos criar uma chave SSH personalizada. Para fazer isso, digite o local do arquivo padrão e substitua id_ALGORITHM pelo nome da chave personalizada.
    
    ```shell
    > Enter a file in which to save the key (/home/YOU/.ssh/id_ALGORITHM):[Press enter]
    ```
    
	 No prompt, digite uma frase secreta segura:
    
    ```shell
    > Enter passphrase (empty for no passphrase): [Type a passphrase]
    > Enter same passphrase again: [Type passphrase again]
    ```

2. **Verificar a Chave SSH**: Para garantir que a chave foi gerada corretamente, execute o seguinte comando para listar os arquivos no diretório `.ssh`:
    
    ```bash
    ls -lha ~/.ssh
    ```
    
    Você deverá ver dois arquivos principais: `id_ed25519` (chave privada) e `id_ed25519.pub` (chave pública).
    
3. **Adicionar a Chave SSH ao GitHub**:
    
    - Exiba o conteúdo da chave pública com o seguinte comando:
    
    ```bash
    cat ~/.ssh/id_ed25519.pub
    ```
    
    - Copie a chave exibida no terminal.
    - Acesse o GitHub, faça login e vá até **Settings** (Configurações).
    - No menu à esquerda, clique em **SSH and GPG keys**.
    - Clique em **New SSH key**, cole a chave pública copiada e adicione um título identificando a máquina (por exemplo, "WSL Ubuntu 22.04").
    - Clique em **Add SSH key**.
4. **Testar a Conexão SSH**: Verifique se a conexão SSH com o GitHub foi configurada corretamente:
    
    ```bash
    ssh -T git@github.com
    ```
    
    Se a configuração foi feita corretamente, você verá uma mensagem como:
    
    ```bash
    Hi username! "You've successfully authenticated, but GitHub does not
	provide shell access."
    ```
    
    

#### Passo 2: Criar o Repositório no GitHub

1. **Acesse o GitHub**: Abra o navegador e vá até [GitHub](https://github.com/). Faça login com sua conta.
2. **Criar um Novo Repositório**:
    - Clique no ícone de **+** no canto superior direito e selecione **New repository**.
    - Dê um nome para o repositório.
    - Adicione uma descrição.
    - Escolha a opção **Public** ou **Private**, conforme as preferências da equipe.
    - Marque a opção **"Initialize this repository with a README"**.
    - Clique em **Create repository**.

#### Passo 3: Configurar o Repositório Local no WSL (Ubuntu 22.04)

Agora, vamos configurar o repositório localmente no seu ambiente WSL para começar a colaborar.

1. **Clone o Repositório para o Ambiente Local**: No terminal WSL, utilize o comando `git clone` para clonar o repositório remoto para sua máquina local. Substitua `<URL_DO_REPOSITORIO>` pelo link SSH do repositório, que pode ser copiado da página do repositório no GitHub:
    
    ```bash
    git clone git@github.com:usuario/exercicios-estudos.git
    ```
    
    O repositório será clonado para o diretório `exercicios-estudos` em sua máquina local.
    
2. **Entre no Diretório do Repositório**: Após o clone, entre no diretório do repositório:
    
    ```bash
    cd exercicios-estudos
    ```
    

#### Passo 4: Adicionar Membros com Permissão de Escrita

1. **Acesse a Configuração do Repositório**:
    - No GitHub, acesse a página do repositório recém-criado.
    - Vá até a aba **Settings** (Configurações) e, no menu à esquerda, clique em **Manage access**.
2. **Adicionar Colaboradores**:
    - Clique em **Invite a collaborator**.
    - Adicione os colaboradores pelo nome de usuário ou e-mail e defina a permissão como **Write** (para permitir commits, criação de branches e pull requests).
    - Clique em **Send Invitation** para convidar os membros.

#### Passo 5: Proibir Merge/Push Direto na Branch Master/Main

1. **Configurar Proteção para a Branch Master/Main**:
    - Acesse novamente a aba **Settings** do repositório.
    - Na seção **Branches**, clique em **Add rule** em **Branch protection rules**.
    - Em **Branch name pattern**, insira `main` (ou `master`, se for o caso).
    - Marque a opção **"Require pull request reviews before merging"** para garantir que todas as alterações sejam revisadas antes de serem mescladas.
    - Marque **"Require status checks to pass before merging"**, se estiver usando integração contínua (CI).
    - Marque **"Include administrators"** para aplicar a regra até mesmo aos administradores.
    - Desmarque a opção **"Allow force pushes"** e **"Allow deletions"** para evitar alterações diretas na branch **main**.

#### Passo 6: Adicionar o responsável como Owner

1. **Adicionar o responsável como Owner**:
    
    - No menu **Manage access**, clique em **Invite a collaborator** e adicione o responsável.
    - Após a aceitação do convite, altere a permissão do responsável para **Owner**.
2. **Remover o Criador como Owner**:
    
    - Após o responsável ser configurado como **Owner**, o criador do repositório pode remover a própria permissão de **Owner**. Isso pode ser feito na mesma página de **Manage access**, alterando a permissão do criador para **Admin** ou **Write**.

#### Passo 7: Criar o README

1. **Editar o README**:
    
    - No terminal WSL, no diretório do repositório clonado, edite o arquivo `README.md` com um editor de sua preferência (por exemplo, `nano` ou `vim`):
    
    ```bash
    nano README.md
    ```
    
    Adicione informações básicas sobre o repositório, como o objetivo e instruções de contribuição. Um exemplo de conteúdo:
    
    ```markdown
    # Repositório de Exercícios e Estudos
    
    Este repositório armazena códigos de exercícios e estudos em Python e outras linguagens.
    
    ## Como Contribuir
    
    1. Faça um fork deste repositório.
    2. Crie uma nova branch para suas alterações: `git checkout -b minha-feature`.
    3. Faça commit das suas alterações: `git commit -am 'Adiciona nova funcionalidade'`.
    4. Envie sua branch: `git push origin minha-feature`.
    5. Abra um Pull Request para revisão.
    
    ## Exemplos de uso
    
    Adicione exemplos de como usar os códigos ou bibliotecas do repositório.
    ```
    
2. **Commit e Push do README**: Após editar o README, faça o commit e envie as alterações para o GitHub:
    
    ```bash
    git add README.md
    git commit -m "Adiciona o README inicial"
    git push origin main
    ```
    

#### Passo 8: Criar um `.gitignore` com Prioridade em Python

1. **Criar o Arquivo `.gitignore`**:
    
    - No diretório do repositório, crie um arquivo `.gitignore` com o seguinte conteúdo:
    
    ```bash
    # Python
    *.pyc
    __pycache__/
    *.pyo
    .Python
    env/
    venv/
    .env
    .venv
    pip-log.txt
    pip-delete-this-directory.txt
    *.db
    ```
    
2. **Commit e Push do `.gitignore`**: Após criar o arquivo `.gitignore`, faça um commit e envie para o GitHub:
    
    ```bash
    git add .gitignore
    git commit -m "Adiciona .gitignore com prioridade em Python"
    git push origin main
    ```

```bash
git push
```
