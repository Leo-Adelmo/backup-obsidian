

**1. Padrão do Nome do Branch**

Ao criar uma regra de proteção, é possível especificar um padrão que determinará quais branches serão afetados. Utilizando a sintaxe `fnmatch`, pode-se definir padrões específicos. Por exemplo, para proteger todos os branches que contêm a palavra "release", utiliza-se o padrão `*release*`. Para proteger todos os branches atuais e futuros, o padrão `*` é empregado. É importante notar que o caractere `*` não corresponde a separadores de diretório (`/`). ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**2. Require pull request reviews before merging**

Esta opção assegura que quaisquer alterações propostas por meio de pull requests sejam revisadas e aprovadas por membros designados da equipe antes de serem integradas ao branch protegido. Essa prática é essencial para manter a qualidade do código e detectar possíveis problemas antecipadamente. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**3. Require status checks to pass before merging**

Com esta configuração, a mesclagem de pull requests no branch protegido só é permitida se todas as verificações de status configuradas (como testes automatizados ou análises de código) forem aprovadas. Isso garante que o código atenda aos critérios de qualidade estabelecidos antes de ser incorporado. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**4. Require branches to be up to date before merging**

Esta regra exige que o branch de trabalho seja atualizado com as últimas alterações do branch protegido antes da mesclagem. Isso ajuda a evitar conflitos e garante que o código mais recente seja considerado durante a revisão. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**5. Restrict who can push to matching branches**

Com esta restrição, apenas usuários ou equipes específicas têm permissão para enviar alterações diretamente para o branch protegido. Essa medida adiciona uma camada adicional de segurança, garantindo que apenas indivíduos autorizados possam modificar o branch crítico. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**6. Require signed commits**

Esta opção assegura que todas as confirmações no branch protegido sejam assinadas com uma chave GPG ou uma chave SSH confiável. Isso adiciona uma camada de autenticidade às alterações, garantindo que elas sejam originadas de fontes confiáveis. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**7. Require conversation resolution before merging**

Com esta regra, todas as conversas em pull requests devem ser resolvidas antes da mesclagem. Isso garante que as discussões sejam tratadas adequadamente antes da inclusão do código no branch protegido. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**8. Require linear history**

Esta configuração obriga que o histórico de commits siga um padrão linear, impedindo merges que criem grafos de histórico complexos. Isso facilita a rastreabilidade das alterações no repositório. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**9. Lock branch**

Esta opção bloqueia completamente o branch protegido, impedindo qualquer tipo de alteração. Essa funcionalidade é útil para preservar branches históricos ou finalizados. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))

**10. Allow force pushes**

Por padrão, o GitHub bloqueia force pushes em branches protegidos, mas essa opção permite exceções, caso necessário. Deve ser usada com cautela para evitar perda de histórico. ([docs.github.com](https://docs.github.com/pt/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule?utm_source=chatgpt.com))
