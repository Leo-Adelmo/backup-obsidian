## Introdução

No contexto de desenvolvimento ágil e gerenciamento de projetos de software, a organização do trabalho em diferentes níveis de granularidade é fundamental para o sucesso da equipe. Quatro conceitos essenciais formam a espinha dorsal dessa estrutura hierárquica: temas, épicos, histórias de usuário e tarefas. Compreender essas distinções e como elas se inter-relacionam é crucial para uma comunicação efetiva e execução bem-sucedida de projetos.

Antes de mergulhar em cada termo, vamos ver como esses termos se relacionam entre si. Temas, épicos, histórias e tarefas formam uma hierarquia. No topo estão os temas, que são divididos em épicos, depois histórias de usuário e, finalmente, tarefas. Como cada item se vincula ao item acima (por exemplo, tarefas pertencem a histórias de usuário, histórias de usuário a épicos e épicos a um tema), você deve abordar o processo de estruturação do seu trabalho de cima para baixo.

## O que são temas ágeis?

Temas estabelecem a conexão entre sua estratégia e o trabalho ajudando você a priorizar e entregar o maior valor para clientes e a organização. Como temas representam áreas principais de investimento entre objetivos de negócio e produto, temas ágeis frequentemente se alinham com períodos de planejamento estratégico (como trimestres ou anos).

|                          |                                                                                                                                                                                                                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Definição**            | Temas ágeis são iniciativas estratégicas. Eles descrevem a direção de alto nível para o trabalho de desenvolvimento que ajudará você a realizar seus objetivos. Um tema é a maior unidade de trabalho no desenvolvimento ágil. todos os épicos, histórias e tarefas relacionados ficam sob este guarda-chuva. |
| **Como usar**            | * Conectar o trabalho da equipe de desenvolvimento aos objetivos de produto e negócio.<br>* Definir áreas estratégicas de foco para o trabalho de desenvolvimento ágil.<br>* Organizar corpos de trabalho relacionados em categorias amplas.                                                                  |
| **Exemplo de tema ágil** | *Introduzir melhorias de rastreamento ao nosso aplicativo de ciclismo.*                                                                                                                                                                                                                                       |

## O que são épicos ágeis?

Épicos fornecem um nível de organização entre temas mais amplos e histórias de usuário individuais. Você pode pensar neles como categorias ou pais para histórias de usuário. Épicos ajudam você a levar suas ideias estratégicas adiante enquanto você começa a definir trabalho mais tático.

|  |  |
| --- | --- |
| **Definição** | Épicos ágeis são grandes corpos de trabalho frequentemente englobando várias histórias de usuário. Eles descrevem requisitos principais do produto ou áreas de funcionalidade que definem uma experiência do usuário. Épicos são tipicamente entregues através de múltiplos lançamentos. |
| **Como usar** | * Dividir grandes atualizações de funcionalidade que não podem ser completadas em um único sprint.<br>* Agrupar histórias de usuário menores que não se relacionam diretamente umas com as outras, mas caem sob o mesmo guarda-chuva de funcionalidade (por exemplo, melhorias de UI).<br>* Planejar grandes atualizações quando histórias de usuário ainda não estão definidas. |
| **Exemplo de épico ágil** | *Melhorar a funcionalidade de rastreamento GPS do aplicativo de ciclismo.* |

## O que são histórias de usuário ágeis?

À medida que você desce na hierarquia, há uma mudança de itens de trabalho estratégicos e organizacionais para táticos, como histórias de usuário. Histórias de usuário ajudam você a traduzir seus objetivos, temas e épicos em trabalho de desenvolvimento do dia a dia.

Na maioria dos casos, múltiplas histórias de usuário serão categorizadas em épicos.

|                                         |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Definição**                           | Histórias de usuário ágeis definem uma função ou benefício discreto do produto que cria novo valor para os clientes. Idealmente, você deve ser capaz de completar uma história de usuário dentro de um único sprint. Histórias de usuário são essencialmente o mesmo que recursos do produto — mas reescritos da perspectiva do usuário. A intenção é transmitir como os usuários experimentarão a nova funcionalidade e como ela os beneficiará.                                                                            |
| **Como usar**                           | * Definir uma parte de funcionalidade nova ou atualizada para seu produto relacionada à aparência, capacidades, etc.<br>* Pensar sobre nova funcionalidade do ponto de vista do cliente.                                                                                                                                                                                                                                                                                                                                     |
| **Exemplo de história de usuário ágil** | Histórias de usuário geralmente seguem um formato definido:<br>* Como um [tipo de usuário], eu quero [realizar alguma tarefa] para que eu possa [alcançar algum objetivo].<br><br>Digamos que você planeja introduzir integração com Google Maps como um novo recurso no seu aplicativo de ciclismo. Para reformular isso como uma história de usuário, você poderia dizer:<br>* Como um ciclista, eu quero rastrear minha rota no Google Maps para que eu possa registrar minha distância e seguir direções ao mesmo tempo. |

À medida que você define histórias de usuário, sua equipe pode participar do mapeamento de histórias de usuário. Este exercício ajuda você a visualizar o fluxo das interações do seu cliente com seu produto. Mapas de histórias de usuário ajudam equipes ágeis a pensarem sobre a experiência do usuário com cada parte do produto. Eles também fornecem uma maneira satisfatória de organizar e priorizar o trabalho — em vez de usar um único backlog plano.

## O que são tarefas ágeis?

Tarefas são a última peça da hierarquia e a menor unidade de trabalho. Nem todas as equipes Scrum usam tarefas — às vezes histórias de usuário são detalhadas o suficiente por si só. Mas para recursos mais complexos, tarefas são úteis.

|  |  |
| --- | --- |
| **Definição** | Tarefas são peças específicas de trabalho técnico para uma equipe ágil. Elas representam itens de trabalho de desenvolvimento que devem ser feitos para completar uma história de usuário. |
| **Como usar** | * Definir peças específicas de trabalho técnico que contribuem para uma história de usuário.<br>* Dividir trabalho técnico entre a equipe de desenvolvimento. |
| **Exemplo de tarefa ágil** | *Criar mensagem pop-up no aplicativo para alertar clientes sobre nova integração com Google Maps.* |

Lembre-se: À medida que você estrutura seu trabalho ágil, considere o "por quê" por trás dele. Seus objetivos de produto devem ser um fio de continuidade através de seus temas, épicos, histórias e até tarefas. Esta mentalidade ajudará você a planejar e realizar o trabalho que mais importa.
